# Battery-Swap Resume for Waypoint Missions: DJI Mini 5 Pro + RC2 + DJI Fly

Research date: 2026-09-12. Scope: does a waypoint mission survive a battery swap on a **DJI Mini 5 Pro / DJI RC2 / DJI Fly** setup, with as little manual work as possible for an operator running four batteries.

## Direct answers

1. **Does DJI Fly resume an interrupted mission?** Partially, and only within one continuous flight. DJI Fly has a **Pause / Continue** control that works while the aircraft is still airborne and the app session is unbroken (manual pause, or a "Continue" choice on signal loss). It does **not** have a breakpoint feature that survives landing, powering off, and swapping the battery — the DJI Fly waypoint-mode support article states that stopping a mission (the X/stop control) returns the app to edit mode, not to a resumable state. **Documented** (DJI support), corroborated by **community reports** that a full power cycle drops the mission state.

2. **What does the aircraft do on its own at low battery mid-mission?** It aborts the waypoint mission and executes a normal low-battery RTH, the same firmware-level battery protection used in every flight mode (first warning around 20%, cancellable; second warning around 10%, not cancellable; forced landing if even RTH isn't safe). This happens **regardless of the mission's "On Signal Lost" setting**, including when "Continue" was selected. **Documented** for the general RTH/battery logic; the "it still RTHs even under Continue" specific claim is **community-reported** (mavicpilots), consistent with the documented failsafe design. It cannot be configured off, and DJI Fly does not compute or warn in advance whether a *given mission's length* fits in one battery — that estimate is left to the pilot or third-party planning tools.

3. **Is resume a real, documented enterprise feature that DJI Fly simply lacks?** Confirmed. DJI's own GS Pro FAQ says plainly: missions over 99 waypoints are auto-sectioned, pausing between sections, and pilots "continue the mission by using the 'Resume from Last Stopped Point' function"; separately, "GS Pro is able to continue a mission from a breakpoint, so when the battery is low, pause the mission, swap the battery and continue." This is **documented** on dji.com. But GS Pro never supported the Mini/Air consumer line at all (its aircraft list is Mavic 2 Enterprise/Pro/Zoom, Mavic Pro, Phantom 3/4 series, Inspire 1/2, Matrice 100/200/210/600) — it's now a legacy app. The Mini 5 Pro has **no equivalent** resume feature in DJI Fly; the enterprise equivalent that does still exist is the DJI Dock "resume from breakpoint" mechanism in DJI's Cloud API, which is dock/enterprise-only (see Q4).

4. **Does WPML carry resume/breakpoint fields, and do they apply to consumer aircraft?** Yes, but only in the **dock-to-cloud** side of the ecosystem, not in the WPML file format itself. The `dji-wpml` file spec (template.kml/waylines.wpml) has no breakpoint fields — those live in the separate Cloud API MQTT messages used between a DJI Dock and DJI's cloud server: a `break_point` struct (`index`, `state`, `progress`, `wayline_id`, `break_reason`) reported by `flighttask_progress` and re-sent by the cloud to `issue wayline task` to resume. This is explicitly for the Dock/FlightHub2 pipeline (M30-class docked aircraft), unrelated to DJI Fly or the Mini 5 Pro. **Documented** (github.com/dji-sdk/Cloud-API-Doc).

5. **How do third-party tools handle it?** All the tools examined split a long survey into several battery-sized missions rather than implementing true resume:
   - **FlyPath** (github.com/dronnix-io/FlyPath): `split_waypoints()` divides a lawnmower route into N contiguous sub-missions, one per battery, each exported as its own KMZ (`<name>_1_of_N.kmz`, etc.). See "exact seam handling" below — it repeats one shared point, it does not resume state.
   - **MavenRoute** (mavenpilot.com): has an "automatic mission splitting tool" — set a max-waypoint cap, get multiple KMZ files out. No resume.
   - **Litchi**: for the Mini 5 Pro (unsupported by Litchi's own SDK-based engine), the relevant path is **Litchi Mission Hub's "DJI Fly importer"**, which exports a KMZ that DJI Fly flies natively — so resume behavior is whatever DJI Fly's native engine offers (i.e., none across a power cycle), not Litchi's. Litchi's own app-level Pause/Resume (for older, SDK-connected drones) explicitly does **not** remember the last completed waypoint across a battery change — users must scroll to and manually re-select the waypoint. Confirmed as still true, and requested as a feature, on Litchi's own forum as of 2024.
   - **WaypointMap**: no mention of battery-based mission splitting or resume in its site or Mini 5 Pro-specific page; **could not verify** it has this feature at all.
   - **MavenBridge**: a file-transfer utility (KMZ → RC via USB), not a mission planner; it doesn't split or resume missions itself.

6. **What do experienced pilots actually do?** The consistent community-reported procedure: watch the battery (many pause around 20–25%), hit Pause, RTH or manually fly home, land, swap battery (and memory card, for safety), power back on, reconnect, and either (a) on the older DJI Pilot/Smart Controller stack, tap Play to auto-resume from the last waypoint, or (b) on DJI Fly with a pre-split mission, load and fly the next KMZ part starting at the shared seam point. Reported failure modes: forgetting the last waypoint number and having to scroll through hundreds of entries; one user reporting that on DJI Fly-class software "continuing a mission only works as long as no other mission is started or the controller is switched off" (i.e., resume does *not* survive a power cycle) — directly conflicting with an older report of the DJI Pilot/Smart Controller combo surviving a power-off in 2020. Both are **community reports**, not documentation, and the discrepancy likely reflects different apps/aircraft generations rather than one being simply wrong.

## Evidence

### DJI Fly / Mini 5 Pro native behavior (documented)
- DJI Fly's Waypoint Flight support article lists the Mini 5 Pro as supported and describes **End of Flight** (RTH/Land/Hover/Back to Start) and **On Signal Lost** (RTH/Land/Hover/Continue) settings, a mid-flight **Pause/Continue** control, and confirms that stopping a mission (X) returns to edit mode rather than a resumable state: https://support.dji.com/help/content?customId=en-us03400007343&documentType=artical&lang=en&paperDocType=paper&re=US&spaceId=34
- General DJI RTH/low-battery logic (first warning ~20% cancellable, second ~10% not cancellable, forced landing if RTH unsafe): https://repair.dji.com/help/content?customId=en-us03400006776&spaceId=34&re=US&lang=en&documentType=artical&paperDocType=paper

### Community confirmation that low-battery RTH overrides "Continue" (community-reported)
- mavicpilots.com thread "DJI Waypoint Behavior on Low Battery": a moderator states the low-battery failsafe "is baked into the firmware and operates regardless of what mode you fly in," and another pilot reports an Air 3 audibly announcing "battery level low, returning to home in 10 seconds" mid-waypoint-mission. https://mavicpilots.com/threads/dji-waypoint-behavior-on-low-battery.144489/

### GS Pro resume-from-breakpoint (documented, but not applicable to Mini 5 Pro)
- DJI's own GS Pro FAQ: 99-waypoint auto-sectioning with "Resume from Last Stopped Point," and "GS Pro is able to continue a mission from a breakpoint, so when the battery is low, pause the mission, swap the battery and continue." https://www.dji.com/ground-station-pro/faq
- GS Pro's supported-aircraft list (Mavic 2 Enterprise/Pro/Zoom, Mavic Pro, Phantom 3/4 series, Inspire 1/2, Matrice 100/200/210/600 family) — no Mini or Air-series consumer drone is supported, confirming the resume feature never reached the Mini line: https://www.dji.com/ground-station-pro
- Community account of the procedure working end-to-end on a Mavic 2 Pro Enterprise Dual with DJI Pilot + Smart Controller, including a full power-off/battery-swap/power-on cycle before resuming: https://mavicpilots.com/threads/mapping-a-multi-battery-route-with-dji-pilot-and-the-smart-controller.83246/ (note a later reply on the same thread disputes that resume survives a controller power-off — conflicting community reports, not resolved by documentation)
- Community account (Mavic 2 Enterprise Dual on GS Pro) matching the documented flow: "When low battery level is reached, the mission is paused and the aircraft will RTH. After you changed the battery, press the 'pause' button... to resume the mission at the next waypoint." https://mavicpilots.com/threads/battery-change-during-dji-gs-pro-mission.80324/

### WPML / Cloud API breakpoint fields (documented, enterprise/dock-only)
- WPML overview and file format (template.kml / waylines.wpml / res) has no breakpoint or resume fields — it only describes the archive format: https://github.com/dji-sdk/Cloud-API-Doc/blob/master/docs/en/40.specification/80.dji-wpml/10.overview.md
- The actual breakpoint/resume mechanism lives in the **DJI Dock** wayline-management docs: "Resume from Breakpoint... If wayline mission can not be completed in one flight... resuming from breakpoint allows the task to restart from the breakpoint but not from the start," with the dock relaying breakpoint coordinates/index/progress to the aircraft via the cloud: https://github.com/dji-sdk/Cloud-API-Doc/blob/master/docs/en/30.feature-set/20.dock-feature-set/50.dock-wayline-management.md
- The underlying MQTT `break_point` struct fields (`index`, `state` [on segment/on waypoint], `progress`, `wayline_id`, `break_reason` — including a code `773` "Wayline interrupted due to low battery causing return to home") appear only in the dock-to-cloud `flighttask_progress`/`issue wayline task` API, not in the WPML file itself and not reachable from DJI Fly: https://github.com/dji-sdk/Cloud-API-Doc/blob/master/docs/en/60.api-reference/20.dock-to-cloud/00.mqtt/20.dock/00.dock1/50.wayline.md
- DJI Pilot 2's wayline management (the enterprise app tier below Dock) only covers uploading/downloading/favoriting wayline files with a cloud workspace — no breakpoint/resume language at all: https://github.com/dji-sdk/Cloud-API-Doc/blob/master/docs/en/30.feature-set/10.pilot-feature-set/60.pilot-wayline-management.md

### Third-party tools (mixed: vendor docs + source read)
- **FlyPath** `split_waypoints()`, read directly from source (`grid_planner.py`, dronnix-io/FlyPath, cloned at research time): splits a lawnmower route into `n_missions` contiguous groups by *line count* (not raw waypoint count), computed as `base, rem = divmod(n_lines, n)`. Each sub-mission after the first is built by taking `prev_last = chunk[-1]` from the previous sub-mission and prepending it to the next: `chunk = [prev_last] + chunk`. In other words, **the seam is a single shared coordinate, deliberately duplicated as the last waypoint of mission *k* and the first waypoint of mission *k+1***, so the flight paths visually and physically join up with no coverage gap. There is no state carried beyond that shared point — no waypoint index, no progress counter, no mission ID; each part is flown as an independent, self-contained KMZ mission that the pilot loads separately. The README documents the same design for user-facing purposes and states plainly: "The RC replaces one mission at a time, so choose which part to send... and repeat for each part" — i.e., resume across parts is a fully manual load-and-fly step, not automated. Repo: https://github.com/dronnix-io/FlyPath
- A near-identical `split_waypoints()` in the same file (for the full-auto/photo-count case, splitting by waypoint count rather than line count) uses the same shared-seam-waypoint approach, confirmed by its own docstring: "consecutive missions share a seam waypoint so the coloured paths join up with no gap."
- **MavenRoute**: "automatic mission splitting tool in the photogrammetry planner, so you can set a max waypoint limit and export the project as multiple smaller KMZ missions" — same split-into-files pattern, no resume language found: https://www.mavenpilot.com/mavenroute-curved-paths-kmz-missions/
- **MavenBridge**: a USB desktop bridge to move KMZ files onto a DJI Fly controller; no split or resume functionality of its own: https://www.mavenpilot.com/mavenbridge/
- **Litchi**: app-level compatibility list (Litchi's native SDK control) stops at Mini 2/Mini SE/Air 2S/Mavic Air 2/Mavic 2/older — it does **not** include Mini 5 Pro, Air 3, or Mavic 3/4, confirming the Mini 5 Pro can only be flown via a KMZ hand-off to DJI Fly, not Litchi's own engine: https://flylitchi.com/help
- Litchi's Mission Hub added a "DJI Fly importer" (export as DJI-format KMZ) specifically for SDK-unsupported newer drones (Mavic 3, Air 3, Mavic 4, Mini 5): reported via community threads and a third-party converter site, e.g. https://mavicpilots.com/threads/importing-litichi-waypoint-missions-into-dji-fly-app.152617/ and https://www.litchiutilities.com/docs/import.php (community reports/vendor tool pages, not DJI documentation)
- Litchi's own in-app Pause/Resume (for the SDK-connected drones it still supports) is documented to require manual re-selection of the restart waypoint after any battery change — no automatic "resume from last completed waypoint": https://flylitchi.com/help (see "Start/Pause/Resume Mission"); confirmed still unimplemented and requested as a feature on Litchi's forum as late as June 2024: https://forum.flylitchi.com/t/pausing-waypoint-mission-to-change-a-battery/8689 and https://forum.flylitchi.com/t/restart-from-waypoint-after-last-completed-to-allow-mission-battery-changes/10198
- **WaypointMap**: no battery-split or resume feature found on its homepage, tutorial, or Mini 5 Pro-specific page: https://www.waypointmap.com/ , https://www.waypointmap.com/Home/Tutorial , https://www.waypointmap.com/drone/dji-mini-5-pro-automated-mission-flight-planning — treated as **could not verify** rather than confirmed absent, since the site may not document every feature.

### Practical pilot procedure (community-reported)
- Step-by-step account of a 4-battery, ~1400-photo mapping mission on a Mavic 2 Pro Enterprise Dual with DJI Pilot + Smart Controller: pause around 25% battery, RTH, power off, swap battery (and memory card), power on, reconnect, tap the lit-up Play button to confirm resume from the waypoint, continue. https://mavicpilots.com/threads/mapping-a-multi-battery-route-with-dji-pilot-and-the-smart-controller.83246/
- A reply on that same thread asserts the opposite — that continuing only works if the controller was never switched off — which was not reconciled by any documentation found; flagged as a live disagreement between pilots, possibly reflecting different app/aircraft generations.
- Litchi forum pilots doing multi-battery mapping report manually noting the last waypoint reached (watching the screen, "pick an easy point to stop... at the end of a straight line") because there is no automatic memory of progress: https://forum.flylitchi.com/t/pause-and-resume-mapping-mission-to-change-batteries/10171

## Could not verify
- Whether DJI Fly on the Mini 5 Pro (or any current consumer aircraft) has ever silently added a "resume after battery swap" capability post-firmware-update; no release notes or support article mentions it as of this research date.
- Whether WaypointMap has an undocumented battery-split or resume feature not visible on its public site.
- Whether the RC2's file system genuinely offers "no built-in import/export" for KMZ (one search summary claimed this) versus a documented KMZ-drop folder — not independently confirmed against a primary DJI source in this pass.
- The precise mechanism (if any) behind the conflicting mavicpilots.com report that "continuing a mission only works as long as... the controller is switched off" — unclear whether this applied to DJI Pilot, DJI Fly, GS Pro, or a specific firmware version, since the poster did not specify.
- Reddit was not consulted (behind login wall, per instructions); YouTube was excluded per instructions. Both may contain additional pilot procedure/failure-mode reports not reflected here.
