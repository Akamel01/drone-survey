# The first write to the controller — 2026-09-12

Whether the RC2's mission folder could be **written** — not merely read — was the
longest-standing unknown in the loading design. Everything before this was forum
reports. This records the first write, done from the Linux host over USB with
`jmtpfs`.

## What was loaded

Four Missions for the rehearsal flight, generated by `scripts/mission/make_mission.py`
over the rectangle the operator marked on the Controller: 204 × 268 m, 5.48 ha.

| | |
|---|---|
| Area | 240 photo positions over 10 lines, extended one pass beyond the boundary |
| Standard | 80% forward and 70% side Overlap, gimbal −80°, 80 m, 5 m/s |
| Resolution | 1.08 cm per pixel |
| Split | two balanced parts per variant, 120 and 121 waypoints, under DJI Fly's 200 ceiling |
| Variants | fly-through and stop-at-point, so the rehearsal flies the comparison that sets the default |

## The slot mapping

The operator created eight slots in DJI Fly by saving copies of an existing
mission. Four were overwritten:

| Slot | Holds | Size |
|---|---|---|
| `0F4D66A4-FE61-4228-98FB-D0B41846EE8C` | fly-through, part 1 | 7,488 B |
| `D9957576-7D8F-4C38-9882-3FFC9854129E` | fly-through, part 2 | 7,549 B |
| `4EB8CF63-ECE2-4B3E-9434-EBF1DB8AD20C` | stop-at-point, part 1 | 7,486 B |
| `9DC4E654-858D-4F1F-A415-72590E124484` | stop-at-point, part 2 | 7,547 B |

Left alone: `888F850E…` (the operator's own test Mission, and our dialect
reference), plus `B0C76D15…`, `F76CFC51…` and `AE07F06C…` as spares.

**Each slot's previous file was copied off before being replaced**, to
`~/drone/rc2/backup-015221/` on the host.

## How the write was verified

Not by the copy's exit status. The mount was released, the Controller re-mounted,
and each file's checksum compared with its source: **all four identical**. That is
the rule [ADR 0016](../adr/0016-mission-generation-and-loading-for-the-rc2.md)
sets, and it is the same lesson as ODM reporting success over a collapsed mesh.

Overwriting in place did not work as a plain copy; the existing file had to be
removed first. A loader must do the same.

## Still unknown, and each matters

- **What DJI Fly displays.** Mission names live in DJI Fly's own database, not in
  the file, and the thumbnails under `map_preview/` were generated from the
  missions that used to be in those slots. The list may therefore show the old
  names and old pictures over the new flight plans. Only opening the list on the
  Controller answers it.
- **Whether opening a Mission causes DJI Fly to rewrite it.** FlyPath reports
  that the app rebuilds `waylines.wpml` from `template.kml` on save or cloud
  sync. Re-reading a slot after the operator opens it will show whether our file
  survives being viewed.
- **Whether the aircraft flies it**, takes a photograph at each waypoint, and
  holds −80°. That is the proving flight (#10).

## An aside worth recording

Saving copies of a Mission in DJI Fly **rewrote the original too**: the operator's
test Mission went from 2,034 bytes at 17:41 to 1,995 bytes at 18:50. Nothing was
lost — the analysed copy is on the host and its findings are in
[the dialect reference](rc2-native-mission-2026-09-12.md) — but it is a reminder
that the app rewrites these files on its own schedule, and that anything we care
about must be copied off rather than left on the Controller.
