# Architecture review — 2026-10-25

Scope: whole repo, hot spots from `git log` (last ~3 months). Read `CONTEXT.md`, `docs/adr/`, and the prior reviews (#65 one home per fact, #258 Mission lifecycle / area editing / Load / Card Ledger / planner client) before scanning; nothing below re-proposes a closed child of #258, and where a finding extends one it says so.

## Ranked deepening opportunities

### 1. B2 upload bypasses the shared token-refresh seam — `web/lib/b2.ts:160-179`
- Files: `web/lib/b2.ts` (`authorize`, `b2Fetch`, `afterReauthorizing`, `uploadFile`), callers `web/lib/missionStore.ts` (`writeMission`, `writeSpec`).
- Problem: every read/delete/list call goes through `b2Fetch` (`web/lib/b2.ts:120-132`), which retries once on a 401 by reauthorizing the cached session; `uploadFile` authorizes its upload URL through `b2Fetch` but then performs the final PUT with a bare `fetch` (`web/lib/b2.ts:169-179`). A rotated or invalidated upload token therefore fails the whole upload with no retry, and the failure mode differs from every other B2 call.
- Proposed change: route the final PUT through the same reauthorization path (or factor the upload into a `b2Fetch`-style helper that refreshes `authorizationToken`), so upload behaves like list/download/delete.
- Expected effect: one failure mode and one retry policy for all B2 writes; the upload path becomes testable through the same seam as the reads; removes a latent "works on reads, fails on writes" regression.
- Strength: Strong. Size: S.

### 2. `MapPane` still carries pure geometry helpers after area editing moved out — `web/components/MapPane.tsx:83-88`
- Files: `web/components/MapPane.tsx` (`toLngLat`, `mPerLon`, `eastOf`, `footprintGeoJSON`, GeoJSON builders at 90-159), `web/lib/mission.ts` (its own `mPerLon` at 89-92), `web/lib/areaEditing.ts`.
- Problem: #260 moved the drawing rules into `areaEditing.ts`, but the map adapter still owns ~100 lines of pure coordinate math and GeoJSON construction (`toLngLat`, `mPerLon`, `eastOf`, `footprintGeoJSON`) that are not reachable from a test and duplicate the metre-per-degree math in `mission.ts:89-92` (different constants: `111320` vs `111412.84`).
- Proposed change: move the pure helpers into `web/lib/mission.ts` (or a `mapGeometry.ts` next to `areaEditing.ts`) with unit tests, leaving `MapPane` as the MapLibre/React adapter; reconcile the two `mPerLon` constants.
- Expected effect: the coordinate math becomes testable and stops drifting between adapter and core; smaller adapter; one place decides metres-per-degree.
- Strength: Worth exploring. Size: M.

### Checked and fine: Load orchestration

`scripts/mission/load.py` already implements the `Controller` seam from `load_core.py` as `MountedController` (`scripts/mission/load.py:141`), used by `verify_ledger` at `scripts/mission/load.py:275`. `scripts/mission/load_test.py` imports `load_core` and exercises `build` (cluster 14, `scripts/mission/load_test.py:657-670`) and `announce_refusal` (cluster 12, `scripts/mission/load_test.py:564-576`) through `TempMountedController` (`scripts/mission/load_test.py:213`). The only untested piece is `remount` (`scripts/mission/load.py:108`), a thin fusermount/jmtpfs wrapper whose failure mode is a `LoadFailed` with the Controller's own message; not worth a ticket. No finding, no ticket.

### 4. No repository entry file at the root — `web/CLAUDE.md:1`
- Files: root has `CONTEXT.md` and `README.md` but no `CLAUDE.md`/`AGENTS.md`; `web/CLAUDE.md:1` is only `@AGENTS.md`, and `web/AGENTS.md:1-9` is the Next.js boilerplate.
- Problem: an agent landing at the repo root has no routing to `CONTEXT.md`, `docs/design.md`, `docs/adr/`, or the web app's conventions; the only agent file is framework boilerplate. Walkability depends on the README pointing at `CONTEXT.md`.
- Proposed change: add a short root `AGENTS.md` (and `CLAUDE.md` twin) routing to `CONTEXT.md`, `docs/design.md`, `docs/adr/`, `web/`, `scripts/mission/`, `nodes/`, `pipeline/`; keep it under ~40 lines.
- Expected effect: two-hop reachability for "what is X" and "what else moves"; one routing row instead of README hunting.
- Strength: Strong. Size: S.
- Low risk: documentation only, no behaviour change.

### 5. `OP_OF` is `Partial`, so an action can silently have no op — `web/lib/missionRepository.ts:97`
- Files: `web/lib/missionRepository.ts` (`OP_OF` at 97), `web/lib/outbox.ts` (`OutboxOp`).
- Problem: `OP_OF: Partial<Record<MissionAction, OutboxOp>>` already maps the five row actions to ops, but `Partial` means an action with no entry compiles and is treated as "no op to enqueue", so a new `MissionAction` can be added without deciding whether it waits for the network.
- Proposed change: make it `Record<MissionAction, OutboxOp | "local">`, with `"local"` as the explicit local-only marker, so every action declares its fate and a missing entry fails `tsc`.
- Expected effect: a new verb cannot be added without stating whether it syncs or stays local; the repository/outbox boundary becomes checkable by the compiler.
- Strength: Speculative. Size: S.

## ICM audit (System map form, audit only)

- Entry file: none at root. `web/CLAUDE.md` is a one-line `@AGENTS.md` (`web/CLAUDE.md:1`) and `web/AGENTS.md` is Next.js boilerplate (`web/AGENTS.md:1-9`), so the web app has no project routing either. The real entry points are `README.md` and `CONTEXT.md`.
- Facts with more than one home: (a) the metre-per-degree constant appears in `web/lib/mission.ts:89-92` and `web/components/MapPane.tsx:85` with different values; (b) B2 key literals live in `web/lib/keys.ts` and `scripts/mission/keys.py` but are kept in sync by `fixtures/store-keys.json` and a self-test on both sides, so that one is intentional and guarded.
- Ghosts/leftovers: `web/CLAUDE.md` carries no project content; `scripts/mission/load.py` still contains the pre-#261 orchestration despite `load_core.py` existing; `web/components/MapPane.tsx` retains geometry helpers after `areaEditing.ts` took the rules.
- Change-impact (first order): changing a Mission state name touches `web/lib/model.ts` (`MissionState`, `LIVE_STATES`, `ARCHIVED_STATES`), `web/lib/missionRecords.ts` (`deriveMissions`), `web/lib/missionView.ts` (`STATE_LABEL`), and `web/components/MissionList.tsx` rendering; changing a store key touches `web/lib/keys.ts`, `scripts/mission/keys.py`, and `fixtures/store-keys.json` (both self-tests must still pass); changing the Card Ledger shape touches `web/lib/model.ts`, `scripts/mission/b2_status.py`, and `fixtures/card-ledger.json`.
- `map/` shelf verdict: not worth building here. One `CONTEXT.md` plus a short root `AGENTS.md` (finding 4) is enough; the repo already has a strong glossary and ADR set, and a scaffold would duplicate them. Revisit only if a second agent repeatedly fails the walk test.
